# Base SinLLaMA (no task adapter) — tested results across the 4 components

**Condition tested:** `SinLLaMA-merged-base` with **no task-specific LoRA
adapter loaded** — i.e. the shared base model on its own, given the same
task prompt a trained adapter would receive. This is the ablation that shows
what a task adapter is actually buying over the base model.

SinLlama covers 4 NLP components: **grammar correction, headline
generation, article summarization, and style rewriting** (see repo
`CLAUDE.md`). Searching the repo for this exact condition (base model, no
adapter) turned up real test artifacts for **2 of the 4** — grammar and
style. Headline and summarizer have no such run anywhere in the codebase;
every headline/summarizer eval script found (`eval_hirunews_v19.py`,
`test_headline_v18/19/20.py`, `summarizer/abstractive/8_evaluate_summarizer.py`)
always loads its task adapter. That gap is reported below rather than
filled in with invented numbers.

| Component | Base/no-adapter test exists? | Scored against gold? |
|---|---|---|
| Grammar | Yes — `Tested_results/Stage6/sinllama_base_noadapter_stage6_predictions.jsonl` | No — raw predictions only (see below) |
| Style | Yes — `eval/style_frozen_baseline_outputs.json` → `eval/style_frozen_scored_results.json` | Yes — fully scored, 100 articles × 5 styles |
| Headline | **No** | — |
| Summarizer | **No** | — |

## 1. Grammar — base model, no adapter

**Source:** `Tested_results/Stage6/sinllama_base_noadapter_stage6_predictions.jsonl`
(+ `.manifest.json`), also duplicated at the folder root as
`Tested_results/sinllama_base_stage6_predictions.jsonl` (same 286 rows,
byte-identical predictions, earlier/fuller manifest). Generated by
`scripts/predict_grammar_sinllama_base.py`, the explicit ablation script:
*"SinLLaMA-merged-base + the unchanged grammar prompt + no PEFT adapter."*

**Run config (from the manifest):**
- Base model: `models/SinLLaMA-merged-base`, `adapter: null`, `task_adapter_loaded: false`
- Input: `data/grammar_stage6_inputs.jsonl`, all 286 Stage 6 rows (`complete_frozen_comparison: true`)
- Prompt: identical Alpaca template/instruction used by the trained grammar adapters
- Decoding: greedy (`do_sample: false`), `max_new_tokens: 256`
- Run date: 2026-08-27, wall time 1991.5s for all 286 rows (≈7.0s/row avg latency)

**No gold-scored metrics exist for this run yet** — the Stage 6 private gold
file lives on a different machine (`/Users/nisalfonseka/.../stage6/private/grammar_stage6_gold.private.jsonl`,
per `Stage6/sinllama_v27_stage6_full_metrics.md`'s reproduction command) and
hasn't been scored against these particular predictions in this repo. What
follows is a direct behavioral characterization computed from the raw
predictions themselves (286/286 rows, no external gold needed):

| Behavior | Count | % of 286 |
|---|--:|--:|
| Severe repetition — output ≥3× the input's character length | 216 | 75.5% |
| Output ends with a stray `###` delimiter artifact | 70 | 24.5% |
| Output stays in a plausible length band (0.8×–1.5× input) | 63 | 22.0% |
| Exact unchanged copy of the input | 0 | 0.0% |
| Mean output/input character-length ratio | — | **10.33×** |
| Max output/input character-length ratio | — | 26.57× |

**Read:** without the grammar LoRA, the base model overwhelmingly fails to
do the task cleanly — it doesn't just "not fix errors," it loses the ability
to stop, echoing/looping the input sentence over and over in **3 out of 4**
outputs (e.g. row `s6-0003`: the 12-word input `ඒ සදහා පැරිස් ඔලිම්පික්
නිර්දේෂය...` gets repeated ~12× before truncating at the 256-token budget).
A quarter of outputs also leak a raw `###` template artifact into the
response text. Only about 1 in 5 outputs land anywhere near the expected
output length. For contrast, the **trained** `sinllama_v27` grammar adapter
scored on this same Stage 6 set (`Stage6/sinllama_v27_stage6_full_metrics.md`):
57.0% exact-match accuracy, ROUGE-L 0.9924, Char-F1 0.9932 — those numbers
aren't directly comparable to the table above (different metric families,
adapter run was gold-scored, base run wasn't), but the qualitative gap —
near-universal repetition loops vs. near-perfect surface fidelity — is the
same story the style and summarizer ablations tell independently.

To gold-score this run: obtain the Stage 6 private gold file and run
`scripts/score_grammar_stage6_full_metrics.py --predictions
Tested_results/Stage6/sinllama_base_noadapter_stage6_predictions.jsonl
--gold <gold-path> --output
Tested_results/Stage6/sinllama_base_noadapter_stage6_full_metrics.md
--stage-name stage6 --system-name "SinLLaMA base (no adapter)"`.

## 2. Style — base model, no adapter

**Source:** `eval/style_frozen_baseline_outputs.json` (raw generations) →
scored in `eval/style_frozen_scored_results.json` under `no_adapter_baseline`.
Full pipeline/provenance documented in `eval/STYLE_FROZEN_HOLDOUT_EVAL.md`;
summarized here for the base-only condition specifically. 100 frozen-holdout
articles × 5 styles (500 generations), identical production prompt used for
both systems.

| Style | Critical fact pres. | Full fact pres. | Number pres. | Content sim. | Length score | Style divergence |
|---|--:|--:|--:|--:|--:|--:|
| Formal | 17.50% | 17.83% | 31.02% | 32.51% | 3.92% | 94.44% |
| Editorial | 16.69% | 17.91% | 30.42% | 29.58% | 2.12% | 94.59% |
| Sports | 18.05% | 19.12% | 28.29% | 32.86% | 3.24% | 94.60% |
| Youth | 17.24% | 17.98% | 29.22% | 31.46% | 3.91% | 94.52% |
| Feature | 17.77% | 18.99% | 27.62% | 33.99% | 3.21% | 94.89% |

Style classification (n-gram similarity classifier, 500 base outputs):
**23.8% accuracy** / 25.33% precision / 22.0% F1 — close to chance among 5
classes, meaning the base model's output for each style prompt doesn't
actually read as belonging to that style.

**Read:** without the style adapter, critical-fact preservation collapses to
~17–18% (vs. 73–85% with the adapter — see `eval/STYLE_FROZEN_HOLDOUT_EVAL.md`),
length compliance to ~2–4% (vs. 48–87%), and style divergence from the
source sits at ~94–95% across every style, meaning the base model isn't
reliably rewriting the source article at all, let alone in the requested
style.

## 3. Headline — not tested in this condition

No no-adapter run exists. `eval_hirunews_v17.py` / `eval_hirunews_v19.py`
and `scripts/test_headline_v18/19/20.py` all load `headline_sinllama_v*`
before generating. The closest available signal is **not equivalent**: v17's
own measured behavior (`CLAUDE.md`, "Headline" section) shows it stops at
~7 words regardless of a longer requested band, but that's the *trained
v17 adapter* under an unconditioned prompt, not the base model with no
adapter at all.

## 4. Summarizer — not tested in this condition

No no-adapter run exists. `summarizer/abstractive/8_evaluate_summarizer.py`
and the v06/v07 eval scripts all evaluate a specific `summarization_sinllama_v0N`
adapter; none carries a base-only arm. `work/serve_sinai.py`'s mT5 "teacher"
comparison model is a different base architecture entirely, not
`SinLLaMA-merged-base` with the adapter removed, so it isn't a substitute
for this ablation either.

---

## Bottom line

Where the ablation has actually been run (grammar, style), the pattern is
consistent: `SinLLaMA-merged-base` alone is not a usable system for these
tasks on its own — it loops/repeats (grammar: 75.5% of outputs ≥3× the
expected length), barely preserves source facts or the requested length
(style: 2–4% length-score, 17–18% fact-preservation), and drifts far from
the requested style (94%+ divergence). The task-specific LoRA adapters are
what make each component usable, not incidental fine-tuning. Headline and
summarizer don't have this same evidence on file yet — running
`predict_grammar_sinllama_base.py`-style no-adapter generation for those two
components (analogous scripts don't currently exist for them) would be
needed to complete the 4-component picture.
